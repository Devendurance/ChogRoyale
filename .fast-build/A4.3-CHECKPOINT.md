# A4.3 Feedback Layer Checkpoint

Date: 2026-10-23

## Slice
A4.3 cross-app feedback and error states. Completed as one bounded shared-layer slice.

## What works
- One shared `feedback-model.ts` maps 401, 403, 404, 409, 422, 429, 500, 503 and network failures to a consistent notice tone, copy and action.
- `AppNotice` now supports real sign-in and retry buttons in addition to setup links. Buttons keep a 44px target.
- Every authenticated view deduplicates notices by message before rendering. An actionable copy wins over a plain duplicate.
- Session expiry now offers a working Sign in action from the lobby, decks, profile, progress, legacy, settings and commanders surfaces.
- Transient service and network failures offer Try again. Validation failures do not.
- A 409 conflict stays a conflict and states that local work is still on screen. The existing deck conflict flow is unchanged.
- Failed reads still map to unavailable or locked states. No failed read becomes empty, zero, success or a saved claim.
- No global state store, new dependency, route, persistence or combat change was added.
