# A4.1 Settings Checkpoint

Date: 2026-10-23

## Slice
A4.1 settings and account surface. Completed in the existing partial implementation, not rebuilt.

## What works
- `/app/settings` renders the booting gate, Privy login gate, profile failure gate and the authenticated settings screen.
- Display name and avatar editing save through the existing `POST /api/players/onboard`. The save is reported only after the server confirms it, then the screen reconciles from `GET /api/players/me`.
- Reads reuse `GET /api/players/me`, `GET /api/players/avatars` and `GET /api/players/me/wallets`. A bootstrappable 404 provisions through the existing `POST /api/auth/bootstrap` and reads again.
- Wallet addresses, row ids and Privy identifiers are dropped by the model. Only type, chain label, verification and primary state render.
- Settings is reachable from the HUD settings icon and from the profile account panel.
- Mobile-first styles use the existing app tokens, 44px targets, a selected avatar state and a desktop two-column layout.
